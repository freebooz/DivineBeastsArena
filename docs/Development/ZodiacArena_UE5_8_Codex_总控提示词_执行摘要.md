# ZodiacArena UE5.8 总控提示词（执行摘要）

## 1. 纲领原则（最高优先级）

所有开发工作都以该总控提示词为最高约束，优先级高于模块化实现细节：

- 以 **UE5.8 + C++17 + GAS + Dedicated Server 权威架构**为唯一方向；
- 统一走三层架构（Foundation / MobaCore / ArenaGame）并保持模块依赖单向；
- 默认采用 Dedicated Server 掌权 + 客户端纯展示与交互；
- 任何涉及线上能力（登录、会话、匹配、开服、回放、结算）的变更，必须可验证可回归；
- 文档、脚本、构建、测试、发布链路均需闭环。
- 已有目标和安全边界清晰时，默认直接执行可验证最小增量，不反复问询常规细节；外部发布输入缺失时跳过该外部项并继续推进本地工程闭环。
- 默认持续推进：常规阶段切换、常规验证、文档同步、源码小步修改和本地证据补齐均不是确认点；不能将计划输出、等待确认或反复询问作为默认完成状态。

## 2. 开发行为红线

在每次改动前先确认：

1. 是否在对应文档（架构 / 开发 / 部署）有对应说明；
2. 是否符合该项目的中文编码与日志规范（UTF-8 + Text / LogTemp）；
3. 是否有可复用的最小单元拆分（Class / DataAsset / Service）；
4. 是否保留 `TODO` 与验收日志，不将“未完成项”掩盖为完成；
5. 是否满足“**可编译、可运行、可联机、可测试、可部署、可上线演进** 的阶段门槛。

## 3. 当前优先执行顺序（持续推进）

- 阶段 P0：文档对齐、项目主线目标复核、核心构建与后端测试通过；
- 阶段 P1：Foundation 与 MobaCore 建设，补齐基础服务接口与主循环关键数据路径；
- 阶段 P2：ArenaGame 联机主链路（房间/会话/匹配/登录/开服）端到端通过；
- 阶段 P3：PC / 移动 UI、AI/资源/运营、GAS 能力扩展与压测验证；
- 阶段 P4：发布与运维闭环（部署、回滚、观测、CI/CD、合规审计）。

## 4. 验收清单（简化）

每周至少抽检以下项：

- `docs/Architecture/*` 与 `docs/Development/*` 与实际代码目录同步；
- `scripts/production-preflight.ps1` 的关键门禁通过；
- 后端核心用例（至少 `dotnet test --no-build`）通过；
- UE/在线联调链路在本机或预发环境可复现；
- CI 可复现、可回滚、可审计。
