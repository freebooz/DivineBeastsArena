# 01 前台链现状清单与迁移映射

## 1. 本步骤边界

本文件是启动、登录、选服、角色选择与角色创建收敛工作的第 01 步基线。此步骤只记录现有实现、引用关系、重复职责与迁移方向，不新增第二套运行时代码，不修改二进制资产，也不提前改变地图或项目全局设置。

目标链路固定为：

`L_DBA_Boot -> L_DBA_Frontend -> Startup -> AutoLogin/Login/Register -> ServerSelect -> CharacterRosterLoading -> CharacterSelect/CharacterCreate -> EnterWorld`

角色创建固定为四步：`Zodiac + Appearance -> Element -> FiveCamp -> Confirm + CharacterName`。`TeamId` 只表示对局敌我，不从生肖、元素或五营推导。

| 现有实现 | 目标实现 | 迁移办法 |

| `DBACharacterPresentationActor` | Preview Actor/Stage 子系统 | 审计是否携带 GAS、Combat、Replication；符合轻量约束则改造复用，否则仅作兼容输入 |

## 5. 关键引用关系

当前主链可归纳为：

`UDBAGameInstance -> UDBAGameUIManager -> UDBAFrontendFlowController -> UDBAFrontendFlowSubsystem`

`Login/Character Widget -> WidgetController 或直接取 UDBAFrontendFlowSubsystem -> UDBAOnlineAccountService -> UDBABackendFacadeSubsystem -> GameBackendClient`

`UDBAFrontendFlowSubsystem -> UDBAFrontendSessionSubsystem / Travel Subsystem -> ClientTravel`

当前风险点：

1. `UDBAFrontendFlowSubsystem` 同时覆盖登录、角色、村庄、组队、匹配与 Arena，超出“持久前台地图页面状态机”边界。
2. `UDBAGameUIManager` 直接创建并管理登录、角色选择、角色创建等流程 Widget，尚无统一 Screen Layer 契约。
3. 创建 Widget 中仍包含 C++ 原生兜底布局、名称规则和选择状态，Draft/ViewModel/Widget 职责未拆清。
4. 角色创建当前是单个流程 Widget 的选择集合，尚未表达固定四步状态。
5. 现有代码存在 `RequestClientTravel`，需要区分合法的 Frontend-to-Game Travel 与前台页面跳转，后者必须彻底禁止。
6. 默认客户端直接进入 `FrontendMap`，与最小 Boot 地图目标不一致。
7. Content 中同时存在旧 `Models/Zodiac` 与 `DBA/Zodiacs/Chinese` 生肖资源路径，以及 Western Zodiac 数据资产；用途未确认前不得删除或批量改名。

## 6. FiveCamp 与旧概念审计

- C++ 与后端主链已经大量使用 `FiveCamp`，并有五个 FiveCamp 数据资产。
- 本次文本源码扫描未发现运行时主链继续使用 `Faction` 或 `DivinePantheon`。
- `FiveCamp` 当前既用于角色创建，也用于表现主题；固定技能组已有文档和测试契约表明只能由 Zodiac + Element 决定。
- 后续不得新增 Faction/九阵营/FactionSelect；如二进制资产或外部 DTO 中发现旧字段，只能通过显式 Mapper 读取。
