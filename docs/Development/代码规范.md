# 代码规范

## 当前目标

本文定义 DivineBeastsArena / ZodiacArena 的基础代码规范。后续新增功能必须优先保持最小可编译闭环、三层架构边界、服务端权威和可测试性。

## 通用规则

- 统一使用空格缩进，推荐 2 空格或沿用当前文件风格。
- 文件末尾保留换行，去除行尾空格。
- 新增源码文件使用 UTF-8。
- C++/UE 类型使用 `PascalCase`。
- 局部变量和函数参数使用语义化英文命名。
- 不使用中文类名、变量名、函数名或源码文件名。
- 新增代码优先复用现有模块、DTO、Subsystem、Component、DataAsset 和日志分类。

## UE C++ 规则

- `GameCore` 不依赖 `GameMoba` 或 `DivineBeastsArena`。
- `GameMoba` 只依赖 `GameCore` 和 UE/GAS 通用模块，不依赖 `DivineBeastsArena`。
- `DivineBeastsArena` 可以依赖 `GameMoba` 和 `GameCore`。
- 禁止跨模块 include 其他模块 `Private` 目录。
- Build.cs 依赖必须最小化。
- Dedicated Server 不应依赖或执行纯表现模块逻辑。
- 战斗、奖励、结算、充值发货等关键逻辑必须服务端权威。
- GAS 不直接依赖具体 UI；UI 通过 ViewModel、PlayerState、ASC 事件、GameplayTag 或 EventBus 获取数据。

## 测试规则

- 新增或修改后端逻辑时优先运行 `dotnet test`。
- 新增或修改 UE 核心逻辑时补充 `*Tests.cpp` 或给出可执行 UE Automation / PIE Smoke Test 命令。
- 涉及 Dedicated Server 的改动必须说明 Server Target 构建和联机验证方式。
- 涉及 UI、UMG、Blueprint 或资产修改时必须通过对应 MCP 工作流 Compile、Save、PIE Smoke Test 和 Git Diff。

## 文档同步

每个系统细化或实现后，应同步更新对应中文文档，记录：

- 当前目标。
- 所属层级。
- 目录结构。
- 核心类。
- 依赖关系。
- 网络策略。
- PC/移动端策略。
- 测试方式。
- 当前限制。
- 后续 TODO。

## 当前阶段不做

- 不一次性生成大规模不可验证代码。
- 不创建巨型万能 Manager。
- 不绕过现有模块边界。
- 不把 Mock 成功当作真实 Dedicated Server 联机成功。
