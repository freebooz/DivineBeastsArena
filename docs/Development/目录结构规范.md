# 目录结构规范

## 当前目标

本文定义 DivineBeastsArena / ZodiacArena 的目录放置规则。后续新增源码、配置、文档、脚本和资源时，必须先确认所属应用、系统、子系统和三层架构层级。

## 仓库级结构

| 目录 | 职责 |
| --- | --- |
| `DBA_GameClient/` | UE5.8 客户端与 Dedicated Server 工程。 |
| `DBA_GameBackend/` | .NET 后端、Worker、ServerManagement 与测试。 |
| `DBA_GameAdmin/` | Angular 管理后台。 |
| `DBA_GameWebsite/` | Next.js 官网。 |
| `DBA_GameLauncher/` | Tauri + React 启动器。 |
| `docs/` | 仓库级架构、开发、部署和阶段计划文档。 |
| `scripts/` | 仓库级预检、烟雾测试和辅助脚本。 |

## UE 源码结构

当前 UE 源码位于 `DBA_GameClient/Source/`：

| 模块 | 目录 | 层级 |
| --- | --- | --- |
| `GameCore` | `DBA_GameClient/Source/GameCore` | Foundation / 通用基础层 |
| `GameMoba` | `DBA_GameClient/Source/GameMoba` | MobaCore / MOBA 通用层 |
| `DivineBeastsArena` | `DBA_GameClient/Source/DivineBeastsArena` | ArenaGame / 竞技场业务层 |

Target 文件当前位于 `DBA_GameClient/Source/`：

- `DivineBeastsArena.Target.cs`
- `DivineBeastsArenaEditor.Target.cs`
- `DivineBeastsArenaServer.Target.cs`

## 新增文件规则

- 新增 C++ 类名、文件名、模块名、插件名、变量名和函数名必须使用英文 ASCII。
- 源码文件名应与主类名一致。
- 测试文件放入对应模块的 `Private/Tests/` 或既有测试目录。
- 文档放入 `docs/Architecture`、`docs/Development`、`docs/Deployment` 或模块内已有 `Docs` 目录。
- 脚本放入 `scripts/`、`DBA_GameClient/Tools/` 或对应模块已有工具目录。
- 不直接新增或修改 `.uasset` / `.umap` 二进制资产文件。

## 资源与内容目录

- 客户端内容根目录为 `DBA_GameClient/Content`。
- 后续新资源应按 Foundation、Moba、Arena 或当前项目已有 `DBA` 目录结构归档。
- 战斗中使用的大资源必须优先软引用、异步加载或预加载。
- 资源命名必须可审计，避免含空格、中文或特殊符号。

## 当前阶段不做

- 不一次性迁移所有目录到 `/Plugins/Zodiac*`。
- 不通过脚本批量移动用户已有资源。
- 不在无验证的情况下跨应用大范围重排目录。
