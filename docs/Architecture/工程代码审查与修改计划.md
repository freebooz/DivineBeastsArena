## 3. P0 问题清单与修复方案

### P0-1：12 生肖角色子类 mojibake 乱码 + 硬编码资源路径 + ConstructorHelpers 同步加载

- **文件**：12 个生肖角色子类（`Private/GameDBA/Character/Zodiac/DBAZodiacCharacter_*.cpp`）
  - Tiger/Snake/Rooster/Rat/Rabbit/Ox/Pig/Monkey/Horse/Goat/Dragon/Dog
- **问题**：
  1. 全部中文注释为 mojibake 乱码（如 "鐢熻倴鍔ㄧ敾閰嶇疆" 应为 "生肖动画配置"）
  2. 构造函数使用 `ConstructorHelpers::FObjectFinder` 同步加载 SkeletalMesh/AnimBlueprint/Icon
  3. 硬编码资源路径（如 `TEXT("/Game/Models/Zodiac/Tiger/SK_Tiger_Mesh.SK_Tiger_Mesh")`）
  4. 违反 `DBA.DataAsset.NoHardcoding`、`DBA.UI.EventAsync`、`DBA.Log.ChineseOutput` 三项策略
- **引用情况**：仅在 `DBAGameModeBase.cpp::ResolveLobbyPawnClass` 中通过 switch-case + StaticClass() 引用
- **修复方案**：
  1. 新建 `UDBAZodiacCharacterRegistry` DataAsset，承载 `TMap<EDBAZodiac, TSubclassOf<ADBAZodiacCharacterBase>>` 映射
  2. 重构 `DBAGameModeBase::ResolveLobbyPawnClass` 为 DataAsset 驱动查询
  3. 删除 12 个生肖角色子类的 .h 和 .cpp（共 24 个文件）
  4. 资源路径通过 `UDBAZodiacHeroDataAsset` 配置（已存在）
- **状态**：✅ 已完成

- **P0-1 风险**：删除 12 生肖角色子类可能影响以这些类为父类的 Blueprint 资产。需在 UE Editor 中确认。
- **P1-6/P1-7 风险**：改造基类继承关系可能影响 CDO 和蓝图引用。需全面测试。
- **P0-6 风险**：GameMoba 基类修改影响所有继承的 Widget。

### 7.2 回滚策略

- 所有修改通过 Git 版本控制，可随时回滚
- 每个修复点独立提交，便于定位问题
