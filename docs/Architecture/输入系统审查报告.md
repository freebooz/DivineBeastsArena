## 1. 总体架构概览

当前输入系统采用 **PlayerController 集中绑定 + ASC InputID 激活** 的路由模式，核心流程为：

```
硬件输入（键鼠/触屏/手柄）
  → ADBALobbyPlayerController::SetupInputComponent（BindAxis/BindAction/BindKey）
  → HandleSkill01Pressed 等回调函数
  → CastEquippedSkillSlot(SkillSlot)
  → MapEquippedSkillSlotToAbilityInputID(SkillSlot)
  → UDBAAbilitySystemComponent::TryActivateAbilityByInputID(InputID, Target)
  → FindAbilitySpecFromHandle → ASC->TryActivateAbility
```

**关键设计特征**：
1. **使用旧版输入 API**：全项目通过 `UInputComponent::BindAxis` / `BindAction` / `BindKey` 绑定输入，未使用 UE5 推荐的 Enhanced Input System（`UInputAction` + `UInputMappingContext`）。
2. **PlayerController 承载所有输入绑定**：`ADBAZodiacCharacterBase::SetupPlayerInputComponent` 为空实现，Character 自身不绑定任何输入。
3. **GAS InputID 体系**：通过 `EDBAAbilityInputID` 枚举将技能槽位映射到 GAS Ability Spec 的 InputID 字段。
4. **Android 触屏独立桥接**：`UDBAAndroidTouchInputBridge` 组件处理移动端技能轮盘和大招按钮。
5. **观战输入独立组件**：`UDBASpectatorComponent` 管理观战模式下的输入绑定。

| 绑定类型 | 绑定名/键 | 回调函数 | 用途 |

| BindKey | B | `HandleInventoryPressed` | B（背包面板） |

**移动输入 GameplayTag 聚合**：
- 构造函数中通过 `FGameplayTag::RequestGameplayTag(TEXT("Input.Move.Forward"))` 等获取 4 个移动 Tag。
- `HandleMoveForwardPressed` 等函数将 Tag 加入 `ActiveMovementInputTags`。
- `ResolveTaggedMovementInput()` 从 Tag 容器解析出移动向量。
- **设计意图**：统一 PC 键盘输入和移动端虚拟摇杆输入到同一套 GameplayTag 体系。

**相机/镜头控制**：
- `MouseLookSensitivity`、`MouseYawSensitivityScale`、`MousePitchSensitivityScale` 等参数硬编码在 UPROPERTY（EditAnywhere）。
- `ApplyMouseLook()`、`ApplyCameraInput()`、`ApplyCameraZoom()` 处理魔兽世界式镜头控制。
- `TouchLookSensitivity` 和 `bEnableTouchLook` 支持触屏镜头控制。

**问题**：
- **P0-1 使用旧版输入 API**：UE5.8 推荐使用 Enhanced Input System，当前代码使用 `BindAxis`/`BindAction`/`BindKey`，这些 API 在 UE5 中标记为过时但仍可用。Build.cs 声明了 `EnhancedInput` 模块依赖但未实际使用。
- **P0-2 缺少 Input Mapping Context 资产**：Content 目录下未发现任何 `IMC_*`（InputMappingContext）或 `IA_*`（InputAction）资产，无法通过数据驱动配置按键映射。
- **P1-1 输入参数硬编码**：`MouseLookSensitivity = 0.25f`、`MouseYawSensitivityScale = 21.0f`、`CameraZoomStep = 90.0f` 等参数通过 `EditAnywhere` UPROPERTY 暴露，但默认值硬编码在 C++ 中，违反 `DBA.DataAsset.NoHardcoding` 策略。
- **P1-2 BindAction 名称依赖 Project Settings**：`BindAction(TEXT("Skill01"), ...)` 依赖 `DefaultInput.ini` 中的 Action Mapping 配置，C++ 代码中不可见按键映射全貌。

### 2.3 UDBAAndroidTouchInputBridge（Android 触屏桥接）

文件：
- `e:\work\Game\DivineBeastsArena\DBA_GameClient\Source\DivineBeastsArena\Public\GameDBA\Input\DBAAndroidTouchInputBridge.h`
- `e:\work\Game\DivineBeastsArena\DBA_GameClient\Source\DivineBeastsArena\Private\GameDBA\Input\DBAAndroidTouchInputBridge.cpp`

**职责**：处理 Android 平台特有的触屏输入逻辑：
- 技能轮盘（长按展开、拖拽选择、松手释放）
- Ultimate 大按钮（能量满闪烁、冷却遮罩）
- 触屏目标选择（拖拽指示器）

**事件广播**（DECLARE_EVENT）：
| 事件 | 参数 | 用途 |
|------|------|------|
| `FDBAOnSkillWheelShow` | `int32 SkillIndex` | UI 层显示技能轮盘 |
| `FDBAOnSkillWheelHide` | — | UI 层隐藏技能轮盘 |
| `FDBAOnSkillDirectionUpdate` | `FVector2D Direction` | Targeting 系统更新方向指示器 |
| `FDBAOnSkillReleased` | `int32 SkillIndex` | GAS 层触发技能释放 |

**调用方式**：通过 `UFUNCTION(BlueprintCallable)` 由外部（Blueprint 或 Widget）调用 `OnSkillButtonLongPressStart`/`OnSkillButtonDrag`/`OnSkillButtonRelease`。

**设计评估**：
- **优点**：仅在 Android 平台激活，PC 平台不创建，符合平台分离原则。通过事件广播解耦 UI/GAS 层，符合事件驱动策略。
- **P1-4 技能索引硬编码**：`SkillIndex` 0=BasicAttack, 1~4=Skill01~04, 5=Ultimate，映射关系硬编码在注释中，未与 `EDBAAbilityInputID` 枚举统一。
- **P1-5 未接入 Enhanced Input**：触屏输入通过 BlueprintCallable 函数调用，而非通过 `UInputComponent` 或 Enhanced Input 的 Touch 触发器，无法统一输入配置。

### 3.3 ASC Ability 授予与 InputID 绑定

文件：`e:\work\Game\DivineBeastsArena\DBA_GameClient\Source\DivineBeastsArena\Private\GameDBA\GAS\DBAAbilitySystemComponent.cpp`

**授予路径**（`GrantAbilitiesFromFixedSkillGroup`）：
- 按 `EDBAAbilityInputID::Skill01~04` 和 `Ultimate` 授予 `UDBAElementSkillAbility_Generic` 和 `UDBAZodiacUltimateAbility_Generic`。
- 每个 Ability Spec 携带 InputID：`FGameplayAbilitySpec Spec(AbilityClass, 1, InputID, this)`。
- 同时缓存运行配置：`AbilityRuntimeConfigsByInputID.Add(InputID, *RuntimeConfig)`。

**激活路径**（`TryActivateAbilityByInputID`，第 433 行）：
1. 校验 InputID 非 None。
2. `IsInputAbilityOnCooldown(InputID)` 检查冷却（读取 Character 缓存，与 GAS 报告 P1-2 重叠）。
3. `FindAbilitySpecFromHandle` 通过 `Spec->InputID == InputID` 查找。
4. `ResolveSkillCueNameForInputID` 解析 GameplayCue 名称。
5. `ASC->TryActivateAbility` 激活。

**问题**：
- **P2-1 同一 Ability Class 多输入槽授予**：`UDBAElementSkillAbility_Generic` 同一个类被授予 4 次（Skill01~04），通过 InputID 区分。这是 GAS 推荐做法，但冷却查询依赖 Character 缓存而非 GAS 冷却 GE（与 GAS 报告 P1-2 重叠）。

## 8. 问题清单（按优先级分级）

### P0（阻断性，必须优先处理）

#### P0-1：使用旧版输入 API，未接入 Enhanced Input System

- 证据：`DBALobbyPlayerController.cpp:182-219` 使用 `BindAxis`/`BindAction`/`BindKey`；`DBASpectatorComponent.cpp:52-70` 同样使用旧版 API。
- 影响：
  1. UE5 中旧版输入 API 标记为过时，未来版本可能移除。
  2. 无法使用 Enhanced Input 的 Trigger、Modifier、Player Mappable Key 等高级特性。
  3. 按键映射无法通过资产配置，不支持运行时热重载或玩家自定义。
  4. 无法支持多平台输入方案的统一管理（PC/手游/手柄需不同映射）。
- 建议：迁移到 Enhanced Input System，创建 `IMC_Lobby`、`IMC_Arena`、`IMC_Spectator` 等 InputMappingContext 资产，通过 `UEnhancedInputComponent` 绑定 `UInputAction`。

#### P0-2：缺少 Input Mapping Context 资产

- 证据：Content 目录下未发现任何 `IMC_*` 或 `IA_*` 资产。
- 影响：按键映射依赖 `DefaultInput.ini` 的 Action/Axis Mapping 配置，C++ 代码中不可见，无法数据驱动。
- 建议：创建 `IMC_Lobby`、`IMC_Arena`、`IMC_Spectator` 资产和对应的 `IA_*` InputAction 资产。

#### P0-3：DBASpectatorComponent 中文注释乱码

- 证据：`DBASpectatorComponent.h:21-22`、`DBASpectatorComponent.cpp:30,51,55,58,69,77,91,97` 等处大量 mojibake。
- 影响：代码可读性极差，违反 `DBA.Log.ChineseOutput` 策略。
- 建议：修复文件编码（应为 UTF-8 with BOM），恢复中文注释。

#### P0-4：UDBASpectatorInputConfig 为空壳死代码

- 证据：`DBASpectatorInputConfig.h` 声明 `ConfigureSpectatorInput` 但无实现，返回硬编码字符串和常量。
- 影响：误导开发者以为观战输入有配置入口，实际是死代码。
- 建议：删除此类，或改造为持有 `UInputMappingContext` 软引用的 DataAsset。

### P1（重要，应尽快处理）

#### P1-1：输入参数硬编码

- 证据：`DBALobbyPlayerController.h:118-155` 的 `MouseLookSensitivity`、`MouseYawSensitivityScale`、`CameraZoomStep`、`MinCameraDistance`、`MaxCameraDistance` 等 15+ 个 UPROPERTY 默认值硬编码。
- 影响：违反 `DBA.DataAsset.NoHardcoding` 策略，策划无法调参。
- 建议：迁移到 `UDBAInputSettingsDataAsset` 或 `UDBADeveloperSettings`。

#### P1-2：BindAction 名称依赖外部配置

- 证据：`BindAction(TEXT("Skill01"), ...)` 依赖 `DefaultInput.ini`。
- 影响：C++ 代码中不可见按键映射全貌，无法数据驱动。
- 建议：迁移到 Enhanced Input 后，按键映射在 IMC 资产中可见。

#### P1-3：Character 不承载输入绑定

- 证据：`DBAZodiacCharacterBase.cpp:463-466` 的 `SetupPlayerInputComponent` 为空。
- 影响：对局内切换 PlayerController 时输入绑定无法跟随 Character。
- 建议：将对局内的技能输入绑定迁移到 Character 或专门的 `UDBAInputComponent`。

#### P1-4：Android 技能索引硬编码

- 证据：`DBAAndroidTouchInputBridge.h:86` 注释 `0=BasicAttack, 1~4=Skill01~04, 5=Ultimate`。
- 影响：索引映射硬编码，未与 `EDBAAbilityInputID` 统一。
- 建议：通过 DataAsset 配置 Android 技能索引到 InputID 的映射。

#### P1-5：Android 触屏未接入 Enhanced Input

- 证据：`DBAAndroidTouchInputBridge` 通过 BlueprintCallable 函数调用，非 InputComponent 绑定。
- 影响：无法统一输入配置，触屏逻辑与键盘逻辑分离。
- 建议：使用 Enhanced Input 的 Touch Trigger 统一触屏输入。

#### P1-6：槽位映射硬编码 switch-case

- 证据：`DBAZodiacCharacterBase.cpp:57-66` 的 `MapEquippedSkillSlotToAbilityInputID`。
- 影响：新增技能槽位需修改 C++ 代码。
- 建议：通过 DataAsset 或 DataTable 配置槽位→InputID 映射。

#### P1-7：观战 BindAction 依赖外部配置

- 证据：`DBASpectatorComponent.cpp:52,53,56,70` 使用 `Spectator_CycleNext` 等绑定名。
- 影响：同 P1-2。
- 建议：同 P0-1，迁移到 Enhanced Input。

### P2（次要/改善项）

#### P2-1：同一 Ability Class 多输入槽授予

- 证据：`DBAAbilitySystemComponent.cpp:163-166` 同一个 `UDBAElementSkillAbility_Generic` 授予 4 次。
- 说明：这是 GAS 推荐做法，通过 InputID 区分冷却。当前冷却查询依赖 Character 缓存（与 GAS 报告 P1-2 重叠），建议直查 GAS 冷却。

#### P2-3：移动输入 GameplayTag 字符串硬编码
