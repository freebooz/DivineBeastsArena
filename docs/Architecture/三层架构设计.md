# 三层架构设计

## 当前目标

本文记录 DivineBeastsArena / ZodiacArena 在 UE5.8 阶段的三层架构约束。后续代码生成、模块拆分、Blueprint/UMG/资源修改、Dedicated Server 联调和自动化测试，都必须先判断改动属于哪一层，再决定目录、模块依赖和验证方式。

更完整的架构审查、GAS/UI/资源/运营边界和路线图见 [总体架构设计与审查报告](./总体架构设计与审查报告.md)。该报告已按当前总控提示词校准术语：附件中的 `Pantheon` 统一映射为当前项目的 `FiveCamp` 表现包维度。

## 当前仓库映射

当前仓库已经存在 UE 工程 `DBA_GameClient/DivineBeastsArena.uproject`，源码模块暂按以下方式映射到总控提示词中的三层架构：

| 总控层级 | 当前模块 | 职责边界 |
| --- | --- | --- |
| Foundation / 通用基础层 | `GameCore` | 通用账号、配置、日志、数据、网络服务抽象、前端基础能力。不得包含具体十二生肖技能、竞技场胜负规则或 MOBA 专属战斗逻辑。 |
| MobaCore / MOBA 通用层 | `GameMoba` | MOBA 通用角色、队伍、战斗、GAS 基类、状态、技能槽、通用 HUD/ViewModel。依赖 `GameCore`，不得依赖 `DivineBeastsArena`。 |
| ArenaGame / 竞技场业务层 | `DivineBeastsArena` | 十二生肖、竞技场流程、具体 UI、地图机制、具体技能、资源绑定和产品业务。可以依赖 `GameMoba` 与 `GameCore`。 |

后续如迁移到插件化命名，可逐步演进为 `ZodiacFoundation`、`ZodiacMoba`、`ZodiacArenaGame`，但不得通过一次性大规模重命名破坏当前可编译状态。

## 依赖规则

- 允许：`DivineBeastsArena -> GameMoba -> GameCore`。
- 允许：`DivineBeastsArena -> GameCore`。
- 禁止：`GameCore` 依赖 `GameMoba` 或 `DivineBeastsArena`。
- 禁止：`GameMoba` 依赖 `DivineBeastsArena`。
- 禁止跨模块 include 其他模块的 `Private` 目录。
- 禁止循环依赖。
- 禁止将十二生肖角色逻辑写入 `GameMoba`。
- 禁止将 MOBA 专属玩法写入 `GameCore`。

## 网络与 Dedicated Server

- 多人核心逻辑必须服务端权威。
- 客户端只提交输入意图、预测和表现请求，不直接决定命中、伤害、胜负、奖励或充值发货。
- Dedicated Server 不执行 UI、音频、纯 VFX、媒体播放等表现逻辑。
- 表现层通过 GameplayCue、AnimNotify、事件、ViewModel 或数据绑定响应服务端状态。

## 当前阶段不做

- 不一次性重命名现有模块。
- 不直接编辑 `.uasset` / `.umap`。
- 不创建完整十二生肖、完整商城、完整支付、完整移动端上线链路。
- 不为了临时编译通过删除三层边界或服务端权威约束。

## 验证方式

- 检查 `*.Build.cs` 依赖方向。
- 搜索跨模块 `Private` include。
- 搜索 `LogTemp` 和客户端权威逻辑。
- 按涉及模块运行对应构建和测试。
- Unreal 资产修改必须通过对应 MCP 工具完成 Compile、Save、PIE Smoke Test 和 Git Diff。
