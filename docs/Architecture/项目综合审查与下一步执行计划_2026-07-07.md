## 2. UE5.8 客户端 / Dedicated Server

### 2.1 模块结构

- 三个运行时游戏模块：`GameCore`（前端/账号/会话/UI 基类，仅 HTTP/JSON + `GameBackendClient`）、`GameMoba`（GAS/EnhancedInput/AI 基类，依赖 `GameCore`）、`DivineBeastsArena`（游戏主模块，依赖前两者 + `GameBackendClient` 插件）。
- 插件 `Plugins/GameBackendClient/`：后端接入服务层（Auth/Config/Room/Match/Session/Runtime/Player/Ranking/Quest/Wallet/Payment/Shop/Friend/Event/Achievement/Mail/Support/Telemetry/Crash）。
- 三个 Target：`DivineBeastsArena.Target.cs`（`Game`，`DBA_CLIENT=1`）、`DivineBeastsArenaEditor.Target.cs`（`Editor`）、`DivineBeastsArenaServer.Target.cs`（`Server`，`DBA_SERVER=1`，剥离编辑器数据与客户端媒体依赖）。

### 2.2 主要系统

- **GAS**：`DBAAbilitySystemComponent`、属性集 `DBABattleAttributeSet` / `DBAHeroGrowthAttributeSet`、能力 `DBAZodiacAbilityBase` / `DBAElementAbilityBase` / `DBAZodiacUltimateAbility_Generic`、平衡子系统 `DBAHeroBalanceSubsystem` + `DT_HeroBalance`。
- **角色**：`DBACharacterBase` → `DBAZodiacCharacterBase`；十二生肖已从每生肖 C++ 子类收敛为 `DBAZodiacCharacterRegistry` 数据驱动 + `Generic` 动画/VFX 配置。怪物 `DBAMonsterBase` / `DBALobbyTrainingMonster` + `DBAMonsterAIComponent`；守卫 `DBAGuardianBase` 及塔/水晶/雕像子类。
- **战斗**：投射物/法术 `DBASkillProjectileBase`、`DBAFireball/FrostShard/ShadowBolt`、`DBAChainLightning/HolyShield/BloomHealing`；反馈 `DBACombatFeedbackSubsystem` / `DBAEffectTableManager` / `DBAFloatingDamageComponent`；可玩技能 `DBAPlayableSkillComponent` + `DBAPlayableSkillCatalogDataAsset`。
- **UI**：登录/选角 `UDBALoginFlowWidgetBase`、`UDBACharacterSelectWidgetController`、`DBACharacterPresentationActor`；大厅 `UDBAMainLobbyWidgetBase` 等；竞技场 HUD `UDBAArenaHUDRootWidgetBase` 系列；编排 `DBAGameUIManager`。
- **账号/会话**：`GameCore/Account/DBAOnlineAccountService` + `DBAOnlineAccountJson` + `DBAMockAccountService`；`DBALoginFlowSubsystem` / `DBAFrontendSessionSubsystem`；队列/组队 `DBAQueueServiceBase` / `DBAPartyServiceBase`。
- **网络**：`Framework/DBAReplicationGraph`（网格 + AlwaysRelevant 节点）、`RPC/DBARpcHandler` 服务端权威校验、无缝迁移 `bUseSeamlessTravel`、`COND_OwnerOnly` 复制优化、断线重连 `DBAReconnectSubsystem` + 后端 `ReconnectToken`。

### 2.3 编译状态（本次验证）

- 本轮共修复了以下 UE5.8 迁移遗留的编译/链接阻塞，`DivineBeastsArenaEditor Win64 Development` 现已 **构建成功（`Result: Succeeded`，`EXIT:0`）**：
  - `UDBALobbyPlayerHUDWidgetBase.cpp`：`TSoftObjectPtr<UTexture2D>(ObjectPath)` 直接由 `const TCHAR*` 构造在 UE5.8 已失效，改为经 `FSoftObjectPath(ObjectPath)` 构造，并补 `#include "UObject/SoftObjectPath.h"`。
  - `DBALobbyPlayerController.cpp` / `DBASpectatorComponent.cpp`：`Settings->Default*InputMappingContext.Get()` 需要 `UInputMappingContext` 完整类型，补 `#include "InputMappingContext.h"`。
  - `DBALobbyTrainingMonster.cpp`、`UDBASoftwareCursorWidget.cpp`、`DBACharacterPreviewActor.cpp`：UE5.8 中 `FSoftObjectPath` 的字符串构造为 `explicit`，且仅字符串字面量可直接构造；由运行时 `const TCHAR*`/`FString` 变量在**声明初始化位置**内联构造 `TSoftObjectPtr<T>(FSoftObjectPath(FString(var)))` 会触发 most-vexing-parse（被解析为函数声明）。统一改为：经具名 `FSoftObjectPath`/`FString` 中间变量，或经返回 `FSoftObjectPath` 的辅助函数（返回语句为表达式上下文，规避歧义）构造。
  - `ADBAZodiacCharacterBase`：`IIDBACharacterRef` 的纯虚 `IsDead()`/`GetTeamID()` 与基类 `ADBACharacterBase` 的同名函数二义，且原声明缺少定义导致 `LNK2019` 未解析符号。修复为保留接口 `override` 声明并在 `.cpp` 中提供转发基类实现的定义（`return ADBACharacterBase::IsDead();` 等），既满足接口纯虚约定又消解二义。
- 源码层面已无裸 `TSoftObjectPtr(TEXT(...))`/`TSoftObjectPtr(const TCHAR*)` 直接构造的遗留（探查确认），软引用统一经 `FSoftObjectPath` 构造。

### 2.4 十二生肖外观（当前策略）

- 采用“占位模型 + 材质染色”临时方案：`UDBAZodiacVisualDeveloperSettings::bUseTintedPlaceholderMesh=true`（默认），12 生肖共用 `SK_Rosales` 占位骨骼网格，通过 `M_DBA_RuntimeTint` 动态材质 + `DT_ZodiacPlaceholderTints` 染色表按生肖区分 `BodyTint` / `AccentTint`。
- 运行时入口：`ADBACharacterPresentationActor::GetLobbyDisplayMeshCandidatePathsForZodiac`（占位模式仅返回占位网格）、`ApplyZodiacMaterialToMesh`（染色）、`ADBAZodiacCharacterBase::ApplyLobbyVisuals`。
- 详见 `docs/Architecture/Characters/ZodiacCharacterSystem.md` §4.2。切换真实模型：置 `bUseTintedPlaceholderMesh=false` 后按生肖加载 `SKM_DBA_Zodiac_*` / `MI_DBA_Zodiac_*`。

### 2.5 测试

- 约 21 个自动化测试文件、约 55 个 `IMPLEMENT_SIMPLE_AUTOMATION_TEST`（均 `EditorContext | EngineFilter`），覆盖账号/JSON、登录流程、角色构筑、UI/HUD、技能目录、后端客户端服务、AI 展示等。

## 3. .NET 后端

### 3.1 结构

8 个项目（.NET 10）：`Game.Api`（Minimal API + SignalR `LobbyHub` + 健康/指标 + Swagger）、`Game.Worker`（`MaintenanceWorker` + `DedicatedServerMaintenanceWorker`）、`Game.ServerManagement`（`DedicatedServerOrchestrator`）、`Game.Infrastructure`（EF Core `GameDbContext` + 实体 + 迁移 + Redis + JWT/密码鉴权 + 开发种子）、`Game.Shared`（DTO/契约/错误码/Options）、以及 `Game.Api.Tests` / `Game.IntegrationTests` / `Game.ServerManagement.Tests`。

### 3.2 接口分组（36 个端点文件）

- 鉴权/账号/玩家：`AuthEndpoints`（游客/开发/账号登录、注册、刷新、登出、Steam/EOS/WeChat 外部登录[mock]、改/重置密码）、`AccountEndpoints`（`/api/account/characters` 与 `/api/players/me/characters` 角色列表/创建/选择）、`PlayerEndpoints`。
- 匹配/房间/会话/运行时/结算：`RoomEndpoints`、`MatchEndpoints`、`SessionEndpoints`、`RuntimeEndpoints`（DS register/ready/heartbeat/player join-leave/match events）、`SettlementEndpoints`。
- 服务器编排：`GameServerEndpoints`（内部托管 DS allocate/release/list/kill）、`AdminGameServerEndpoints`。
- GameFeatures：Inventory、Ranking、Social（好友+邮件）、Commerce（商城，mock）、LiveContent（公告/活动/成就）、PlayerHistory、VersionAnalytics、SessionReconnect、Payment、Wallet、Quest。
- Admin：`AdminEndpoints` + Payment / Quest / Wallet / ClientVersion 分部端点。
- Config/Launcher/Platform/LiveOps/Feedback/Telemetry（含 `ClientLogEndpoints` / `CrashEndpoints`）。

### 3.3 数据库

- `GameDbContext`（PostgreSQL / EF Core）；实体分布在 `AuthEntities` / `SessionEntities` / `GameEntities` / `GameFeatureEntities`。
- 迁移 4 个：`InitialGameSchema` → `AddPlayerCharactersAndDevAccounts` → `AddPlayerSessionBuildSummary` → `AddPaymentOrderAndQuestTables`（`payment_order` / `quest` / `player_quest` + wallet 表）。

### 3.4 测试与已知缺口

- `Game.Api.Tests` 约 19 文件 / ~133 用例；`Game.IntegrationTests` 1 用例；`Game.ServerManagement.Tests` 5 用例。看板记录最近 `dotnet test` 为 **177 通过 / 0 失败**（后续新增用例后需重跑核对）。
- **测试缺口**：payment、quest、wallet、social、telemetry 端点暂无专门测试文件。
