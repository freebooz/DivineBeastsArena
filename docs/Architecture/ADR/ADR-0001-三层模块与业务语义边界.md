# ADR-0001：三层模块与业务语义边界

状态：已接受  
日期：2026-07-11  
适用范围：DBA_GameClient/Source

## 决策

UE 游戏工程保持以下单向依赖：

~~~
DivineBeastsArena -> GameMoba -> GameCore
DivineBeastsArena -> GameCore
~~~

模块职责：

- GameCore：通用异步、日志、账号与会话、平台、传输 DTO、资源加载和基础 UI。不得新增 Zodiac、Element、FiveCamp、固定技能组或项目资源路径。
- GameMoba：通用 MOBA 战斗抽象、GAS 基类、队伍、目标选择、技能槽和 HUD 协议。不得新增具体生肖、五营、项目 Widget 或 /Game/DBA 资源路径。
- DivineBeastsArena：项目身份模型、固定技能组、项目数据资产、角色、具体 GAS、UI、VFX、地图和赛前流程。

跨层传输使用稳定 FName、GameplayTag、协议字符串或中性 DTO。中性 DTO 只携带数据，不负责推导固定技能组、元素克制或 FiveCamp 表现。

## 迁移例外

GameCore 当前已有身份枚举和冻结构筑代码。它们作为存量迁移白名单保留到 2026-08-31，只允许减少引用，不允许新增文件或扩展业务字段。

白名单由 scripts/validate-unreal-module-boundaries.ps1 管理。新增例外必须同时写明所有者、到期日期、目标模块、删除条件和对应自动化测试。

## 命名规则

- 模块名近期保持 GameCore、GameMoba、DivineBeastsArena。
- Arena 模块内部公共根目录统一为 GameDBA。
- UE 类型遵循 U/A/F/E/I 前缀，项目类型主体统一 DBA 前缀。
- 一个业务身份只允许一个权威 UENUM。
- 不新增 Common、Core、Base 等无明确所有权的跨层桥接文件。
- GameMoba 需要复用 GameCore 类型时直接包含 GameCore 的权威头，不创建同名转发头。
