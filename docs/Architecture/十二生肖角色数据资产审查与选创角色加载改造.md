# 十二生肖角色数据资产审查与选创角色加载改造

## 结论

选择角色与创建角色现在共用 `DA_DBA_ZodiacCharacterSelection` 数据资产。界面不再维护生肖描述、能力倾向或技能名称的独立硬编码；C++ 在数据资产完成异步加载后，通过事件刷新现有文本控件。

## 已接入的权威数据

| 数据来源 | 数量 | 选创角色用途 |
| --- | ---: | --- |
| `DT_HeroBalance` | 12 | 生肖名称、核心定位、团队职责、七项能力倾向、优势与短板。 |
| `DT_SkillNames` | 72 | 每个生肖的被动、四个主动技能和生肖大招名称。 |
| `DT_FixedSkillGroups` | 60 | 生肖与五行元素组合的技能组描述、技能标识和元素共鸣配置。 |

资产路径：`/Game/DBA/Data/Registries/DA_DBA_ZodiacCharacterSelection`。

## 运行时加载链路

1. `UDBACharacterSelectFlowWidgetBase` 与 `UDBACharacterCreateFlowWidgetBase` 读取 `UDBAUIDeveloperSettings::ZodiacCharacterSelectionData`。
2. 两个界面通过 `DBAAsyncAssetLoader` 异步加载 `UDBAZodiacHeroDataAsset`，随后订阅 `OnDataTableLoaded`。
3. 资产异步加载英雄属性表、技能名称表与固定技能组表；完成事件驱动界面刷新，不使用 Tick 或轮询。
4. 创建角色界面根据当前生肖和元素显示完整说明；选择角色界面根据已选角色的生肖和主元素追加同一份说明。
5. 角色展示场景固定使用 `FrontendMap` 中已放置的 `ADBACharacterPresentationActor`，选择与创建界面分别提供不同 UMG 交互，不再在运行时生成展示舞台。
6. 旧 `UViewport` 预览、自动拼接的预览背景与共享舞台解析接口已从两套界面 C++ 基类移除；角色旋转交互只作用于固定关卡中的展示 Actor。

## 审查发现与风险

- 原 `UDBAZodiacHeroDataAsset` 的 `ZodiacHeroDisplayTable`、`ZodiacHeroConfigTable` 和 `AbilitySetSummaryTable` 尚未有对应已落地的权威资产，不能作为当前界面数据源。
- `DT_FixedSkillGroups` 的 `AbilitySetAsset` 仍存在未配置项；当前可展示技能组说明和技能标识，但不能据此断言所有 GAS AbilitySet 资产已经可加载。
- `DT_ZodiacSkillDefinitions.csv` 有源码 CSV，但未发现等价的已导入 DataTable 资产；在其导入并建立校验前，不能把它加入运行时角色流程。
- 英雄基础生命、攻击、防御等真实 GAS 属性集初始化仍应由服务端属性数据资产和 GameplayEffect 驱动；本次界面展示的是平衡属性倾向，不替代权威属性初始化。

## 后续修复顺序

1. 建立并导入 `DT_ZodiacHeroDisplay`、`DT_ZodiacHeroConfig` 与 `DT_ZodiacAbilitySetSummary`，再补齐现有数据资产的旧字段。
2. 为 60 个固定技能组补齐 `AbilitySetAsset` 软引用，并在 Dedicated Server 启动校验中报告缺失项。
3. 将创建和选角界面的说明拆分为可选绑定的标题、定位、属性、技能与元素技能组控件；仍由本数据资产事件驱动更新。
4. 在人工审核中确认十二生肖切换时，关卡中已放置的展示 Actor、说明文本和最终创建请求使用同一生肖与元素组合。
