# Content 角色资源审查与角色清单

## 审查范围与方法

- 范围：`DBA_GameClient/Content`，本次共发现 1478 个文件。
- 方法：按资产目录、命名前缀和关联动画文件进行只读盘点；未修改任何资产。
- 限制：当前官方 Unreal MCP 服务未监听，因此本文不能替代 Asset Registry 的引用链、父类和运行时加载状态审查。所有“用途”均以目录、名称和现有项目命名约定为依据。

## 结论

1. 可用于当前十二生肖展示的主资源为 `/Game/DBA/Zodiacs/Chinese` 下的 12 个 `SKM_DBA_Zodiac_*` 网格、12 个材质实例、12 个 `ABP_DBA_Zodiac_*` 和共用人形骨架；运行时由 `DA_DBA_ZodiacCharacterRegistry` 统一引用。
2. `/Game/Models/Zodiac` 与 `/Game/Animation/Zodiac` 仍保留一组旧命名资源，形成当前/旧两条并行路径，必须以数据资产注册表作为唯一加载入口。
3. Content 中存在五个元素英雄原型蓝图，但未发现同目录的专属角色网格；它们不能在未核实蓝图引用前视为可交付角色。
4. 未发现专属 `BP_*Monster*`、`BP_*NPC*`、`BP_*Enemy*`、`BP_*Boss*` 或 `BP_*Creature*` 资产。怪物和 NPC 当前应主要由 C++ 类、关卡放置或通用角色资源承载，后续需补齐对应资产数据。

## 资源组织风险

1. **生肖资源重复**：当前 `SKM_DBA_Zodiac_*` 与旧 `SK_*_Mesh` 同时存在；动画又位于根目录 `/Game/Animation/Zodiac`，与当前网格不在同一资源域。
2. **角色展示外壳重复**：`BP_DBA_CharacterPresentationActor` 有两份同名资产，可能造成加载优先级和人工编辑对象不一致。
3. **元素英雄不完整**：五个英雄原型只有蓝图和数据资产的可见证据，缺少可直接盘点到的专属网格、骨架、AnimBP 和技能表现资产。
4. **怪物/NPC Content 缺失**：未发现独立角色资产，无法在资源层确认大厅怪物或未来对局单位的视觉、动画和数据绑定闭环。
5. **模板资源混入正式路径**：Rosales、Manny、Quinn 与正式生肖角色共存，必须在注册表中显式标记“正式可选”“临时展示”“开发模板”和“占位降级”。

## 建议的唯一资产入口

1. 玩家选角、创建角色和大厅角色只读取 `DA_DBA_ZodiacCharacterRegistry` 与 `DA_DBA_ZodiacCharacterSelection`，禁止按 C++ 路径或旧目录回退。
2. 将十二生肖正式资源统一收束到 `/Game/DBA/Zodiacs/Chinese`；旧 `/Game/Models/Zodiac` 和 `/Game/Animation/Zodiac` 先标记为迁移来源，待引用审查完成后再清理。
3. 为五个元素英雄、怪物和 NPC 分别建立数据资产、网格、AnimBP、能力配置和展示图的完整清单，再开放到运行时角色注册表。
4. 在官方 MCP 恢复后，执行一次只读 Asset Registry 引用审查，确认实际被 `DA_DBA_ZodiacCharacterRegistry`、关卡与 UI 加载的唯一资产路径。
